# 银行客户流失预测：四模型对比

> 在 **20.37% 流失率**的不平衡数据上，对比决策树、神经网络、随机森林、K 近邻四种算法。
> 这个项目真正想说明的不是「哪个模型最准」，而是 **「87% 的准确率为什么可能是坏消息」**。
>
> **课程项目 · 独立完成**

---

## 一、核心结果

| 模型 | 准确率 | 召回率 | 精确率 | F1 | AUC |
| --- | ---: | ---: | ---: | ---: | ---: |
| 决策树 | 0.7830 | 0.5064 | 0.4533 | 0.4784 | 0.6785 |
| 神经网络（MLP 100×50） | 0.8270 | **0.5573** | 0.5601 | 0.5587 | 0.8101 |
| **随机森林（100 棵）** | **0.8700** | 0.4733 | **0.7782** | **0.5886** | **0.8521** |
| K 近邻（K=5） | 0.8370 | 0.4224 | 0.6264 | 0.5046 | 0.7800 |

### 为什么 0.87 的准确率需要警惕

流失率只有 **20.37%**，所以一个「全部预测为不流失」的傻瓜模型就能拿到 **79.63%** 的准确率。

对照来看：

- 决策树的 0.7830 **低于**这个基线 —— 它几乎什么都没学到
- 随机森林的 0.8700 看似漂亮，但召回率只有 **0.4733**：**一半以上真实流失客户被漏掉**

### 模型选择要看场景

| 场景 | 推荐 | 理由 |
| --- | --- | --- |
| 预算有限，只想精准触达少数客户 | 随机森林 | 精确率 0.7782（判流失的 78% 确实流失） |
| 目标是尽量不漏掉流失客户 | MLP | 召回率 0.5573 最高，AUC 0.8101 次优 |
| — | **不要只看准确率** | 这是本项目最重要的方法论结论 |

### K 近邻的混淆矩阵

|  | 预测不流失 | 预测流失 |
| --- | ---: | ---: |
| **实际不流失**（1,607） | 1,508（TN） | 99（FP） |
| **实际流失**（393） | 227（FN） | 166（TP） |

**227 个真实流失客户被误判为「不会流失」** —— 运营团队会直接放弃这批人的挽留。

## 二、特征重要性（随机森林）

| 排名 | 特征 | 重要性 | 业务含义 |
| ---: | --- | ---: | --- |
| 1 | **Age（年龄）** | **0.2457** | 年龄越大流失风险越高 |
| 2 | EstimatedSalary | 0.1455 | 收入影响对服务费的敏感度 |
| 3 | CreditScore | 0.1420 | 信用评分低者服务受限 |
| 4 | Balance | 0.1376 | 余额低者更易被其他机构吸引 |
| 5 | NumOfProducts | 0.1275 | 持有产品越少，绑定越弱 |
| 6 | Tenure | 0.0854 | 客户年限 |
| 7 | Geography_Germany | 0.0201 | 地区差异 |
| 8 | IsActiveMember | 0.0193 | 活跃度 |

**结论**：流失主要由**人口属性 + 财务结构**驱动（前五项占 80% 重要性），地理与活跃标签几乎不起作用。

> 决策树给出的排序略有不同（年龄 0.22 > 余额 0.16 > 工资 0.15），这是单棵树与集成树的结构差异，不影响「年龄第一」的结论。

## 三、数据与预处理

| 环节 | 处理 |
| --- | --- |
| 数据规模 | 10,000 条客户记录，10 个建模特征 |
| 流失率 | 20.37%（1,607 未流失 / 393 流失，测试集） |
| 缺失值 | 全部字段非空率 100% |
| 特征剔除 | RowNumber、CustomerId、Surname |
| 分类变量 | One-Hot 编码（Geography / Gender / HasCrCard / IsActiveMember） |
| 数值变量 | StandardScaler 标准化 |
| 划分 | 训练 80% / 测试 20%（random_state=42） |

数据来源：和鲸社区「客户流失数据集」。

## 六、局限与改进

| 问题 | 说明 | 改进方向 |
| --- | --- | --- |
| 类别不平衡未处理 | 流失率 20.37%，未做任何调整 | SMOTE 过采样 / 类别权重 / 阈值调优（而非默认 0.5） |
| 未调参 | 四模型均用默认参数 | GridSearch / Optuna |
| 特征工程薄弱 | 仅用原始字段 | 构造 RFM 类特征、年龄分箱、交互项 |
| 单次划分 | 仅一次 80/20 划分 | 5 折交叉验证 + 置信区间 |
| 缺代价敏感分析 | 未量化 FN 与 FP 的业务成本差异 | 引入代价矩阵，按业务 ROI 选阈值 |

**改进后的预期**：在 20% 流失率下，若用 SMOTE + 阈值调优，召回率有望从 0.47 提升到 0.65 以上，代价是精确率下降 —— 需要业务方一起决定平衡点。

## 七、业务建议

1. **按年龄分层运营**：年龄是首要因子，中老年客户需要差异化的产品与服务节奏
2. **从「产品数量」切入**：持有产品少的客户流失风险高，交叉销售是最直接的留存手段
3. **余额预警机制**：对余额持续下降的客户提前触达，而不是等流失后挽回
4. **模型选择匹配场景**：见上文「模型选择要看场景」表
